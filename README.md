## 原文と翻訳時の追加事項の区別

目次と本文は原文の章立てに従い、第17節、参考文献、付録A〜Lの順に掲載する。付録K「メインネットワーク上の例外事象」と付録L「数学記号一覧」も、この版の原文PDF（42ページ）に存在する。

原文の脚注はMarkdownの `[^1]`〜`[^12]` として保持し、HTML・LaTeXでも番号1〜12を変えない。HTMLでは本文の後に「原文の脚注」としてまとめる。翻訳時に追加した補足や疑義は、原文の脚注とは独立した上付きの「訳注1」〜「訳注16」で示す。参照先は「訳注（日本語訳で追加）」の一覧であり、各注から参照箇所へ戻れる。訳注と追加の案内は原文の目次に含めない。

訳注には独立したリンクとアンカーを使い、Pandocの脚注機構に渡さない。このため訳注の追加で原文の脚注番号が繰り上がることはない。原文由来の脚注を加除する変更や、訳注を原文の脚注へ混ぜる変更は検査で検出する。

## 版管理方針

通常のファイル名と既定ブランチには、現在保守している一つの版だけを置く。原文の別バージョンへ移行するときは、移行前の翻訳へ `yellow-paper-ja-<fork>-<upstream-commit>` 形式のGitタグを付け、旧版を参照可能にする。GitHub Releaseは通常作成せず、PDFなどの配布物が必要になった場合に限ってタグから作成する。

複数版の同時掲載が必要になるまでは版別ディレクトリを作らない。これにより、大きな生成HTMLやLaTeXを版ごとに複製せず、リポジトリの履歴と公開URLを安定させる。

## 収録物

本リポジトリは単独で利用できる自己完結した構成であり、収録物は次のとおりである。

- `ethereum_yellow_paper_ja.md`: 編集用の正本
- `split-markdown/`: GitHubで数式を読むための章・付録単位の分割Markdown
- `ethereum_yellow_paper_ja.html`: JavaScriptや外部数式サービスに依存しないMathML版
- `ethereum_yellow_paper_ja.tex`: LuaLaTeX用のLaTeX版
- `LICENSE.md`: CC BY-SA 4.0ライセンス全文
- `NOTICE.md`: 原著への帰属表示と変更内容
- `CITATION.cff`: GitHub向け引用メタデータ
- `CONTRIBUTING.md`: 編集・修正時の規約
- `README.md`: 対応版、収録物、生成・検査手順
- `build.sh`、`style.html`、`tools/`: 生成処理、表示設定、参照対応データ、検査ツール
- `.github/workflows/build.yml`: 生成物・回帰テスト・公開対象のCI検査
- `.gitignore`、`.gitattributes`: ローカルファイルの除外と改行コードの指定

公開対象のファイルは `tools/check_package.py` の一覧で管理する。隠しファイルも公開物の一部であり、切り出す際に含める。公開前には次を実行する。

```sh
python3 tools/check_package.py
```

この検査は、一覧にないファイル・空ディレクトリ、シンボリックリンク、必須ファイルの欠落を検出する。公開対象を意図して変更する場合は、同ツールの一覧も更新する。`python3 tools/check_package.py --list` でファイル一覧を表示できる。チェックアウトの `.git` メタデータだけは検査から除くが、配布ファイルには含めない。

エディタの設定、環境設定、Pythonの仮想環境・キャッシュ、TeX補助ファイル・PDFは `.gitignore` の対象とする。共有するエディタ設定はなく、`.vscode/` は不要である。`.gitignore` は既に追跡されたファイルやフォルダを直接コピーする際の混入を防がないため、公開前の検査では無視対象も含めて確認する。ローカル専用ファイルがある場合は、公開対象だけを切り出したディレクトリで検査する。

## ビルド

HTMLとLaTeXの再生成にはPython 3、Pandoc 3以降を使う。収録する生成物とCIではPandoc 3.1.3を使用しており、別の版では生成結果に差が出ることがある。

```sh
./build.sh
```

Markdownの見出しアンカー、数式、表はGitHubのプレビューで解釈できる形式に正規化している。インライン数式には `$` とバッククォートを組み合わせるGitHub公式の衝突回避構文、表示数式には `math` コードフェンスを用いる。

Markdownは、全文を一つに収録した [`ethereum_yellow_paper_ja.md`](ethereum_yellow_paper_ja.md) と、[`split-markdown/README.md`](split-markdown/README.md) を入口とする分割版の両方を収録する。分割版では本文を `chapters/`、付録を `appendices/` に整理し、参考文献と訳注を入口と同じ階層に置いている。両者の内容と対応原文は同一であり、単一ページ版が編集用の正本である。単一ページ版は全文検索やVS Codeなどでの閲覧に適する一方、数式が非常に多いため、GitHubのプレビューでは途中から正常な数式まで表示できない場合がある。分割版はGitHubが一度に処理する数式数を抑えるための閲覧用生成物であり、別の版や簡略版ではない。

編集後に構文を整形する必要がある場合は、次を実行する。通常のビルドでは、正規化済みかどうかも検査される。

```sh
python3 tools/format_markdown.py ethereum_yellow_paper_ja.md
```

分割版だけを再生成・検査する場合は、次を実行する。

```sh
python3 tools/render_github.py
python3 tools/render_github.py --check
```

原文に対応する節・付録番号と式番号はMarkdownに明示する。式番号は、数式ビューア間の互換性のため `\text{(番号)}` として保持する。`tools/reference_map.json` は原文の73の番号付き見出し、196表示式グループ・360式番号、参照ラベル、32文献の引用対応を記録する。目次はこの73見出しと番号を持たない参考文献から構成する。検査ではこれらと、全数式のMarkdown／HTML間のTeX注釈の一致、原文の脚注と訳注の独立性、リンク・定義項目を確認する。数式内に空行を入れると段落として解釈されるため、整形ツールが空行を除去し、通常のビルドでも検出する。

検査自体の回帰テストは `python3 tools/test_checks.py` で実行できる。一時ファイルに数式の不一致、非表示の式番号、誤った式参照、空アンカー、原文脚注の繰り上がり、原文と訳注の混在、目次への訳注の混入、参考文献の位置の変更を模した変更を加えて検出を確認し、数式内の空行の整形も検査する。意図的な不一致のエラー出力の後、各項目が `PASS` になれば成功である。正本と生成物は変更しない。

`tools/publication.lua` は命令表の説明欄を広くし、訳注を独立した上付きの参照にする。LaTeXでは題名の重複を除いて目次を概要と翻訳版の案内の後に置く。HTMLでは目次をクリックまたはキーボードで折り畳める。表示幅の狭い画面では目次を本文の前へ移し、幅の広い表や別行立て数式は横スクロールで読める。訳注の文字色は明色・暗色とも本文色を明示し、背景と細い罫線で区別する。

PDFまで生成する場合はDockerまたはPodmanを使用する。ホストへのTeX Liveの導入は不要である。

```sh
./build.sh --pdf
```

初回実行時はTeX Liveコンテナイメージの取得が必要になる。目次とリンクを確定するためLuaLaTeXを2回実行する。生成される補助ファイルとPDFは`.gitignore`の対象であり、公開用ソースには含めない。

HTML生成時には、数式書体を表す数学用Unicode文字を、通常の文字とMathMLの `mathvariant` 属性の組合せへ正規化する。これにより、太字・等幅・黒板太字など原典の書体を保ちながら、エディタによる紛らわしいUnicode文字の警告を避ける。
